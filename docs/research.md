# DJ Agent 产品研究：竞品、能力边界与差距分析

> 版本 v0.1 ｜ 2026-11-04 ｜ 状态：研究稿，不做代码
> 目的：回答三件事——同类产品怎么做的、手机端智能体已经能做什么、我们的最小版本离"实际有用"还差什么。

---

## 0. 先把需求说清楚

"DJ Agent，目标用户是没做过 DJ 的小伙伴，能清晰准确找到适合的音乐"——这句话里其实藏着两种需求，必须先切开，否则产品会做成四不像：

| 需求类型 | 用户原话 | 本质任务 | 成功标准 |
|---|---|---|---|
| **A. 听着对** | "现在这个场合/心情，放点什么好" | 场合 → 氛围匹配 → 直接播 | 3 秒内开始放，且用户不切歌 |
| **B. 排得顺** | "我有一堆歌，怎么排、怎么接" | 曲目集合 → BPM/调性 → 顺序与过渡 | 歌单能从头放到尾不违和 |

真正的"DJ 感"来自 B，真正的"小白友好"来自 A。当前 kgJP 的 MVP 只做了 A 的一半（5 场景 9 首），B 完全没做。差距分析（§5）围绕这个断层展开。

## 1. 手机端智能体已经能做什么（这是最重要的外部变量）

结论先行：**"操作手机"这件事不需要我们做，也做不过它们。** 2026 年主流手机智能体已具备屏幕感知、跨应用执行、系统级权限；我们要做的是它们不做的"音乐判断"，再把执行挂到它们或深链上。

| 助手 | 跨应用执行 | 系统能力 | 音乐相关 | 对我们的意义 |
|---|---|---|---|---|
| 华为小艺 | 强（全量模式下跨应用成功率约 95%，默认基础模式仅约 30-35%） | 宣称可调用 2100+ 系统能力 | 播歌走系统音乐 App，无专业选曲 | 可作执行通道；选曲判断是空白 |
| 小米超级小爱 | 中（强在米家生态联动，跨品牌弱） | 米家 6000+ 品牌设备 | 可"放歌"但是通用曲库推荐 | 同上 |
| vivo 蓝心小V | 中偏上（GUI 操作专精） | 本地检索强 | 内容生产向 | 同上 |
| OPPO 小布 | 中（记事儿/闪记强，行业首个端侧 Multi-Agent 内测） | 屏幕理解好 | 无 | 同上 |
| 荣耀 YOYO | 强（首个与微信 A2A 合作，微信操作成功率 98.2%） | 100+ 系统能力开放 | 无 | A2A 模式值得关注：未来可被"外部 agent 调用" |
| 豆包手机 | 强（复旦测评中跨 App 长链路表现最抢眼） | 模拟点击为主，速度慢 | 无 | 证明"通用执行者"路线已有人做 |

**推论**：
1. 通用执行层已被平台厂商占据，且有系统权限壁垒——我们没有胜算，也不该进场。
2. 它们的曲库推荐是"通用个性化推荐"，回答不了"这场合该放什么 BPM、能量怎么走、要不要人声"——**专业判断层是空的**。
3. 微信 A2A、荣耀/华为的系统能力开放意味着：未来我们的 agent 可以被手机助手"调用"来干专业的活，而不是跟它抢活。这是唯一不冲突的生态位。

参考：复旦白泽团队手机智能体测评、QuestMobile 2026-06 月活数据、各家 2026 发布会公开信息（详见 §9）。

## 2. 竞品研究（5 个）

选样逻辑：覆盖"专业曲库 / 元数据工具 / 真人 set 参考 / 自动编排 / 中文场景推荐"五种范式，正好是我们可能踩进去的五条路。

### 2.1 Beatport —— 专业电音曲库（卖歌，不卖建议）

- **页面结构**：顶栏（Genres / Charts / Releases / DJ Charts / Hype / Beatport LINK）→ 首页以榜单卡片和 Release 封面墙为主 → 曲目列表页左侧筛选器，右侧表格（封面、曲名、艺人、Label、Genre、BPM、Key、时长、价格）。
- **主要数据**：曲目元数据极全——BPM、Key（含 Camelot 标注）、Genre/Subgenre、Label、Release Date、时长、价格、榜单排名、波形试听。
- **用户动作**：按 BPM 区间/调性/子流派/发行日期筛选；试听；加入购物车/收藏/Playlist；看 DJ Charts 顺藤摸瓜（track → artist → label）；购买或经 LINK 流式推入 DJ 软件。
- **优点**：元数据最权威、最完整；筛选维度对 DJ 真正有用；榜单与 Label 生态是发现引擎。
- **不足**：**没有"场合语言"**——你必须先知道"我要 124-128 BPM 的 melodic techno"，它才帮得上；对小白等于零。付费墙高，中文内容几乎为零，无移动端体验可言。

### 2.2 Tunebat —— BPM/Key 查询与和声工具

- **页面结构**：搜索框 → 曲目结果页（大字号 Key + BPM + Camelot + Popularity + Energy/Danceability 指标）→ 工具区（Key & BPM Finder 上传分析、Vocal Remover、Mastering、BPM Tapper、Metronome、Key & BPM Changer）。
- **主要数据**：7000 万+ 曲目的 Key / BPM / Camelot / Energy / Danceability / Happiness（部分来自 Spotify 音频特征）。
- **用户动作**：按歌名查参数；上传本地音频分析；按 Key/BPM/Genre 组合筛选找"可混"的曲目；用 BPM Tapper 手动测速。
- **优点**：即时、免登录、Camelot 记法对和声混音极友好；上传分析覆盖未发行曲。
- **不足**：**只给参数不给建议**——知道 BPM 128、Key 8A 之后怎么排、放什么场合，它不管；数据库对冷门/未发行曲覆盖弱；纯工具，无播放落地。

### 2.3 1001Tracklists —— 真人 DJ set 的 tracklist 档案库

- **页面结构**：搜索（Tracklists / DJs / Sources / Tracks / Artists / Labels / Stories）→ 每个 set 一个页面：曲目顺序列表 + 时间戳 + 每首的购买/试听外链（Beatport/Spotify/YouTube/SoundCloud…）+ 该曲被哪些 DJ 放过；另有周榜/趋势榜/All Time 榜。
- **主要数据**：45 万+ tracklist（官方口径，另有资料称 500 万+ 曲目关联），含 set 来源（音乐节/电台/俱乐部/podcast）、时间戳、ID 未识别曲目、曲目跨 set 出现次数。
- **用户动作**：搜某个 DJ/某场 set 的曲目表；看某首歌被谁放过；顺着榜单找当下最被播放的曲目；提交/修正 tracklist（需社区资格）。
- **优点**："专业耳朵"的集体智慧——比任何算法都懂"什么歌接什么歌"；跨 set 数据能反推一首歌的场合适配度。
- **不足**：**只服务已知的 set**，没人提交就没有页面；新 set 有滞后；无音频分析、无个性化、无播放能力；对小白门槛高（要先知道听谁的 set）。

### 2.4 DJ.Studio —— 自动编排（Harmonize）+ 时间线混音

- **页面结构**：桌面端（Win/macOS）时间线编辑器为主视图 → 左侧曲库/导入（rekordbox、Serato、Traktor、Engine DJ、iTunes、Beatport/Beatsource/YouTube 流媒体）→ 顶部 Harmonize 一键排序 → 每段过渡的参数面板（时长、EQ、效果、音量自动化）→ 导出（WAV/MP3/MP4/Mixcloud，自动生成 tracklist）。
- **主要数据**：BPM、Key（Camelot 体系）、Energy Level（Mixed In Key 模块）、Cue Point、Stem 分离结果、过渡参数。
- **用户动作**：导入曲目 → 一键 Harmonize 自动按 BPM/调性排序 → 手动微调每段过渡 → 加效果/自己采样 → 导出成品或推 Mixcloud。
- **优点**：把"排得顺"这件事自动化到几乎零门槛；和声/节拍匹配是确定性算法，不靠模型即兴；导出即成品，对新手正反馈极强。
- **不足**：**桌面软件、无移动端**；面向"做 mix 成品"而非"现在放什么"；无场合/情绪输入；订阅 $9/月或 $159 买断，且导出需付费；对"我就想现在听点对的歌"这类需求过重。

### 2.5 网易云音乐「私人漫游·场景模式」+ 场景歌单 —— 中文场景推荐的代表

- **页面结构**：首页 → 私人漫游入口 → 顶部场景栏目条（25 种场景）→ 播放页（大封面 + 歌词/评论）→ 歌单广场（场景化命名，如"独处时刻""日落大道"）。
- **主要数据**：场景标签（曲风/情绪/生活场景三类，共 25 种：说唱、电音、R&B、伤感、欢快、治愈、运动、下雨天、打游戏、驾车、洗澡、咖啡厅…）、听歌行为画像（播放/收藏/跳过/红心/评论情绪）、歌单收藏量。
- **用户动作**：选场景 → 直接进入连续播放；切歌/红心/扔垃圾桶表达偏好；切换熟悉/默认/探索模式；收藏歌单。
- **优点**：**场景语言最接近普通用户**（"下雨天""咖啡厅"就是人话）；推荐即时可播、零学习成本；中文曲库与情绪标签贴合本土。
- **不足**：推荐是黑盒——**不告诉你为什么这首合适，也不给 BPM/能量/人声维度**；无法按"我要纯器乐、不要太熟的歌、能量要往上走"这类专业诉求筛选；不能导出为可编排的歌单结构；平台锁定（只能在网易云里听）。

## 3. 横向能力矩阵

| 能力 | Beatport | Tunebat | 1001Tracklists | DJ.Studio | 网易云场景 | **kgJP 现状** |
|---|---|---|---|---|---|---|
| 用"场合/情绪"做输入 | ✗ | ✗ | 半（要靠 DJ/set 名） | ✗ | ✓（25 场景） | ✓（5 场景） |
| BPM / Key / Camelot 元数据 | ✓ | ✓ | ✗ | ✓ | ✗ | ✗ |
| 能量曲线 / 人声-器乐维度 | 半（Energy 标签） | 半（Energy 数值） | ✗ | ✓（Energy Level） | ✗ | 半（instrument 字段） |
| 曲目顺序 / 过渡编排 | ✗ | ✗ | 半（真人已排好） | ✓（Harmonize） | ✗ | ✗ |
| 推荐理由可解释 | ✗ | ✗ | 半（谁放过） | ✗ | ✗ | ✓（理由模板） |
| 一键播放落地 | ✗（要买/推流） | ✗ | ✗（外链） | ✗（导出文件） | ✓（站内） | ✓（深链唤起酷狗，真机验证） |
| 移动端可用 | 弱 | ✓（Web） | ✓（Web） | ✗ | ✓ | ✓ |
| 中文 / 本土内容 | ✗ | 半 | ✗ | ✗ | ✓ | ✓ |
| 学习成本 | 高 | 低 | 中 | 中 | 极低 | 极低 |
| 价格 | 单曲付费 | 免费 | 免费+广告 | $9/月 | 会员 | 免费 |

**读法**：没有任何一家同时具备"场合语言 + 专业参数 + 可解释理由 + 一键播放"。这四条的交集就是我们的位置。

## 4. 与手机厂商智能体的差异（回答你的第一个问题）

| 维度 | 手机端智能体（小艺/小爱/小V…） | DJ Agent（我们的定位） |
|---|---|---|
| 强项 | 系统权限、跨 App 执行、设备生态 | 音乐判断：场合→参数→曲目→顺序 |
| 曲库 | 通用平台曲库，热度/个性化驱动 | 精选 + 可解释标签（BPM/能量/人声/熟悉度） |
| 输出 | "帮你打开音乐 App 放歌" | "放这几首、按这个顺序、因为这样" |
| 失败模式 | 执行成功但选曲平庸，用户还是切歌 | 判断准但执行依赖深链/宿主 |
| 关系 | **宿主 / 执行通道 / 未来 A2A 调用方** | **被调用的专业能力**，不抢它的活 |

结论：不做通用执行，做"垂直判断 + 极简执行"。执行层复用（深链、系统深链能力、未来 A2A），判断层自建——这是唯一不与历史产品冲突的生态位。

## 5. 当前最小版本 vs 实际使用的差距

当前 MVP：5 个场景（focus/tired/restless/nostalgia/bgm）、9 首曲库、打分选曲、推荐理由、深链唤起酷狗（真机验证通过）。

| # | 差距 | 具体表现 | 用户会怎么骂 |
|---|---|---|---|
| G1 | **曲库太小** | 9 首覆盖 5 场景，同一场景反复出现同一首 | "就这几首？" |
| G2 | **缺 BPM/Key/能量元数据** | 无法回答"能不能接上""能量要不要往上走" | "DJ 连 BPM 都不知道？" |
| G3 | **没有顺序编排** | 只给单曲，不给"这一小时怎么放" | "我要的是一晚上的歌单" |
| G4 | **场景颗粒度粗** | 5 个场景 vs 网易云 25 个；无"婚礼/咖啡馆/带娃/开车" | "没有我这个场合" |
| G5 | **无偏好记忆** | 不记得用户讨厌什么、听过什么（仅进程内去重 5 首） | "怎么又推这首" |
| G6 | **单平台锁定** | 只有酷狗；用户用网易云/QQ 音乐就废了 | "我不用酷狗" |
| G7 | **理由偏模板** | 理由来自字段拼接，不是"这首为什么适合这个场合"的推理 | "理由像机器写的"（它就是） |
| G8 | **无成品交付** | 不能导出歌单/不能分享给朋友/不能生成可播列表 | "怎么发给别人？" |

**判断**：G1/G4 是"量"的问题，可批量化解决；G2/G3 是"质"的问题，决定产品是不是 DJ Agent 而不是"场景电台"；G5/G8 是留存与传播问题。G2/G3 不做，产品就与网易云场景歌单同质，且更弱。

## 6. 怎么才有实际价值（不冲突的楔子）

### 主张

**把"场合"翻译成"参数 + 顺序 + 理由"，然后一键播出来。**

现有产品要么只有场合语言（网易云），要么只有参数（Beatport/Tunebat），要么只有编排（DJ.Studio），要么只有参考答案（1001Tracklists）。**翻译层是空的**。这就是楔子。

### 具体形态（本期可验证的最小闭环）

输入一句人话："周六下午咖啡馆，客人不多，别太吵，别放太熟的歌。"
输出一张卡片：

```
60 分钟 / 14 首 / 能量从 3 爬到 6 再落回 4
① 《X》 96 BPM · 8A · 纯器乐 · 冷门 —— 开场铺底，不抢谈话
② 《Y》 100 BPM · 9A · 女声气声 —— 与①同调，人声轻，自然接上
...
⑭ 《Z》 92 BPM · 8A · 器乐 —— 回到①的调，收尾闭环
[一键播放整张]  [复制歌单]  [为什么这样排？]
```

三件事必须同时成立才有价值：
1. **翻译可解释**：每个参数选择都对应场合约束（"别太吵"→ 能量 ≤5；"别放太熟"→ 熟悉度低）。
2. **顺序有依据**：BPM 相邻差 ≤4、Camelot 相邻（同调/±1/关系调）、能量走一条曲线。
3. **落地无摩擦**：深链直达播放（已真机验证），不要求用户装新播放器。

### 不与历史产品冲突的三条边界

1. **不建曲库、不碰版权、不做播放器**——只做索引与判断，播放交给酷狗/网易云/QQ 音乐。
2. **不做专业 DJ 工具**——不碰 rekordbox/Serato/Traktor 的领地（打碟、Cue、Loop、硬件）。
3. **不做通用助手**——不跟小艺/小爱抢"打开 App、发微信、订酒店"。

### 价值验证（先立指标，再谈功能）

| 指标 | 定义 | 本期目标 |
|---|---|---|
| 首播成功率 | 给出建议后用户实际点播比例 | ≥ 70% |
| 不切歌率 | 播放后 90 秒内未切歌 | ≥ 60% |
| 决策完成时间 | 从输入场合到开始播放 | ≤ 60 秒 |
| 理由命中 | 用户认可"说得对"的比例（人工抽问） | ≥ 50% |
| 复用率 | 7 日内二次使用 | ≥ 30% |

## 7. 本期不做（明确排除）

| 不做 | 理由 |
|---|---|
| 自动混音 / 生成 mix 成品 | DJ.Studio 已做到极致，重资产且与"找歌"核心无关 |
| 曲库/版权/播放器 | 重资产、法律风险，且让产品变成"又一个音乐 App" |
| 专业 DJ 软件功能（打碟、Cue、Loop、BPM 拉伸） | 目标用户是小白，做了也用不上 |
| 通用手机操作（发微信、订票、控家居） | 手机厂商智能体的绝对领地 |
| UGC 歌单社区 / 评论 / 关注 | 冷启动无内容，且与网易云正面冲突 |
| 音频指纹识别（听歌识曲） | Shazam/ACRCloud 成熟，调用即可，不必自研 |
| 多平台同时支持 | 本期只做酷狗深链（已真机验证），验证判断层价值后再扩 |
| 会员/付费体系 | 未验证价值前不做商业化 |
| 实时 BPM 分析（上传音频测速） | Tunebat/Mixed In Key 已成熟，本期用现成元数据 |

## 8. 下一步（研究转行动的最小验证，仍不写产品代码）

1. **建 ground truth**：收集 20 条真实场合描述（朋友口述/社交平台原话），人工标注"理想 BPM 区间、能量、人声偏好、熟悉度"，作为评测集。
2. **补元数据**：把曲库从 9 首扩到 30 首，每首补 BPM / Key(Camelot) / 能量 1-10 / 人声-器乐 / 熟悉度。BPM/Key 用 Tunebat 类工具查，人工复核。
3. **做离线对照实验**：让当前打分器 vs "BPM+能量+Camelot 排序器"在同一评测集上出歌单，人工盲评"哪个更像懂行的 DJ 排的"。
4. **验证结论**：若参数化排序明显优于现状 → 判断层成立，进入实现；若差异不显著 → 说明"场合→参数"映射本身不成立，需要换楔子（例如改做"跟某首参考曲相似的歌"）。
