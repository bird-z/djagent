# 不用浏览器唤起酷狗：三条路径

> 回答：能直接命令唤起，但**通道取决于命令在哪台设备上执行**。
> 这不是酷狗的问题，是设备边界的物理限制。

---

## 核心事实

**我的沙箱是一台 Linux 虚拟机，你的手机是另一台设备。**
我在沙箱里执行任何命令，都碰不到你手机上的酷狗 —— 除非中间有一条通道。

三条路径按可行性排序：

---

## 路径 1：手机本地执行（不需要 Agent）

**手机自己就能直接唤起酷狗，任何终端类 App 都行。**

```
am start -a android.intent.action.VIEW -d "kugou://start.weixin?{...}"
```

或在 Termux 里：
```
am start -a android.intent.action.VIEW -d "kugou://start.weixin?%7B%22cmd%22%3A212%2C%22jsonStr%22%3A%7B%22hash%22%3A%22...%22%7D%7D"
```

但这和 Agent 无关 —— 就是你手机上跑条命令，和我无关。

---

## 路径 2：Agent 通过 adb 唤起手机（唯一"Agent 直接控制"的路径）

**前提：手机连到我的沙箱，或无线调试连到同一局域网。**

沙箱里已经有 `adb 1.0.41`，手机连上后 Agent 可以：

```bash
# 打开指定歌曲
adb shell am start -a android.intent.action.VIEW \
  -d "kugou://start.weixin?%7B%22cmd%22%3A212%2C%22jsonStr%22%3A%7B%22hash%22%3A%22a4713521e4754b8ed3f09af1e41756e5%22%2C%22filename%22%3A%22%E5%82%85%E6%A2%A6%E5%BD%A4%20-%20%E6%BD%AE%E6%B1%90%22%7D%7D"

# 只打开酷狗
adb shell monkey -p com.kugou.android -c android.intent.category.LAUNCHER 1
```

### 实测状态（2026-11-03）

- `adb devices` → **空**
- `adb connect 192.168.238.14:5555` → **Connection refused**
- `adb mdns services` → **无发现**

**说明你手机目前没开 USB 调试 / 无线调试**。这是预期行为 —— 安卓默认关闭，需要手动开。

### 要打通，你需要：

**方案 A：USB 连接 + 开启 USB 调试**
1. 设置 → 我的设备 → 全部参数 → 连点 7 次「MIUI 版本」
2. 设置 → 更多设置 → 开发者选项 → 开启「USB 调试」
3. USB 连接沙箱所在电脑 → 手机弹窗选「文件传输」
4. 手机上弹「允许 USB 调试吗」→ 允许

⚠️ **但沙箱是虚拟机**，USB 直通到沙箱内不可靠。可能需要 USB over IP 或让宿主机转发 —— 这一步我没法替你做。

**方案 B：无线调试（MIUI 11+，安卓 11+）**
1. 开发者选项 → 无线调试 → 开启
2. 点「使用配对码配对设备」→ 记下 IP:端口 + 6 位配对码
3. 在沙箱执行：
   ```bash
   adb pair <配对时显示的IP:端口>   # 输入 6 位码
   adb connect <无线调试页显示的IP:端口>
   ```
4. 之后 `adb devices` 应该能看到设备

⚠️ **同一 Wi-Fi 下才行**。你手机连的 Wi-Fi 和这台沙箱所在网络（192.168.238.x）要互通。

**方案 C：你自己在手机上执行，不需要打通**
- 手机装 Termux（F-Droid 版），把命令贴进去跑。和 Agent 无关，但最快验证协议是否可用。

---

## 路径 3：Agent 在你电脑上唤起电脑的酷狗（另一条路）

如果目标是"Agent 推荐的歌在**电脑的酷狗客户端**里播"，那需要的不是 adb，而是：

- **Windows**：`start kugou://start.weixin?...`（cmd）或 `start "" "kugou://..."`
- **macOS**：`open "kugou://start.weixin?..."`

但 Agent 工具跑在沙箱里，**不直接控制你的电脑**。
要做这条，得在你的电脑上装一个本地 agent（WorkBuddy 客户端本体的 Code 模式），把命令发到那台电脑执行。

---

## 我的沙箱实测小结

| 尝试 | 结果 |
|---|---|
| `xdg-open kugou://...` | 工具存在但无桌面环境，不会真的唤起 |
| `open kugou://...` | 这是 Linux，`open` 是 macOS 命令，不适用 |
| `adb devices` | 空，无设备 |
| `adb connect 192.168.238.14:5555` | Connection refused |
| `adb mdns services` | 无发现 |

**结论**：通道当前是断的。不是协议问题，是你手机没开调试、也没连到沙箱。

---

## 建议顺序

1. **先做路径 2 方案 B（无线调试）**：不用插线，MIUI 支持，同一 Wi-Fi 即可。
   配对成功后 Agent 就能在对话里直接让你手机放歌。
2. 如果嫌麻烦，**先做路径 1 方案 C**：Termux 手动跑一次，
   验证 `kugou://start.weixin` 协议本身在 MIUI 上是否可用 ——
   这一步不管走不走 Agent 化都得做，先确认协议再打通通道，顺序才对。
3. 电脑端唤起（路径 3）优先级放低：等手机端验证过协议，再考虑。

---

## 一句话结论

- **命令唤起：可以**，`adb shell am start` 就是命令唤起，不需要浏览器。
- **但前提是 Agent 能"够到"那台设备**。目前够不到，需要你开一次无线调试并配对。
- 协议本身是否会被 MIUI 拦截、是否会真的播放，依然是**未验证状态**，
  必须真机测试后才能下结论。
