## 0. 结论先行

**最终形态不是一个 App，是三层产品矩阵**：

```
① 判断层（资产）  场合卡 + 8 轴 + 规则集 → 以 API / Skill / MCP 形式被调用
② C 端（获客）    手机 H5/PWA → 场景卡 → 场前编排 → 现场盘 → 唤起酷狗播放
③ B 端（变现）    Web 控制台：多场地排程、场合卡管理、播放监控与复盘
```

落地顺序：**H5/PWA 先行（4-6 周可验证）→ 原生 App（留存）→ B 端控制台（变现）→ 生态接入（被手机助手/其他 agent 调用）**。

理由一句话：**C 端解决"有没有人用"，B 端解决"谁来付钱"，判断层解决"凭什么是我"。**

## 1. 六种形态逐一评估

评分：★ 1-5，越高越好。"可分享"指能否一条链接发给别人。

| 形态 | 冷启动成本 | 可分享 | 执行可靠性 | 留存潜力 | 变现路径 | 开发周期 | 综合 |
|---|---|---|---|---|---|---|---|
| **A. 手机 H5 / PWA** | ★★★★★ 零安装 | ★★★★★ 链接直达 | ★★★☆ 需浏览器允许唤起 | ★★☆ 无推送/无桌面图标 | ★☆ 广告/导流 | 4-6 周 | **★★★★** |
| **B. 微信小程序** | ★★★★★ 微信内零安装 | ★★★★★ 卡片分享最强 | ★ 无法直接唤起外部 App（平台限制） | ★★★ 有订阅消息 | ★★★ 可挂广告/会员 | 6-8 周 | ★★☆ |
| **C. 原生 App（iOS/Android）** | ★★ 需下载 | ★★ 需装 | ★★★★★ 深链/后台/离线全可控 | ★★★★★ 推送+桌面 | ★★★★ 订阅 | 10-16 周 | ★★★★ |
| **D. 桌面 Web（编排台）** | ★★★ 打开即用 | ★★★★ 链接 | ★★★ 播放在手机端 | ★★★ 工作场景刚需 | ★★★ B 端 | 6-8 周 | ★★★★ |
| **E. Skill / MCP / API（被调用）** | ★★★★★ 无界面 | — | ★★★★ 依赖宿主 | ★ 无自有用户 | ★★ 按调用计费 | 1-3 周 | ★★★ |
| **F. 硬件播放盒（B 端）** | ★ 需发货 | — | ★★★★★ 专用设备 | — | ★★★★★ 硬件+服务费 | 16 周+ | ★★（过早） |

### 各形态的关键约束

**A. H5/PWA**
- 优点：一条链接就能用，微信/短信/二维码都能传；改版即生效，不用过审。
- 硬伤：Android Chrome 可用 `intent://` 或 `kugou://` 唤起酷狗（已验证思路），**iOS Safari 对第三方 scheme 限制严格**，大概率只能"复制链接 + 打开酷狗"两步。
- 结论：**Android 优先**，iOS 做降级（复制深链 → 提示"在酷狗中打开"）。

**B. 微信小程序**
- 优点：分享体验最好，微信内传播成本最低。
- 硬伤：**小程序不能直接拉起站外 App**（`navigateToMiniProgram` 只限小程序间）。需要"复制深链 → 用户手动打开酷狗"，体验断一层。
- 结论：**不做首发**。可作为"分享落地页"（别人发来的歌单在小程序里看，但播放在 H5 完成）。

**C. 原生 App**
- 优点：深链、后台轮询（设备桥）、离线缓存、推送、桌面图标——留存的所有杠杆都在这里。
- 硬伤：双端开发成本、上架审核（音乐类需版权说明）、iOS 深链仍受系统限制但比浏览器宽松。
- 结论：**第二阶段做**，先做 Android（与已验证的深链路径一致），iOS 后补。

**D. 桌面 Web 编排台**
- 优点：场前编排是"坐下来排"的场景，桌面天然合适；能量曲线时间线在大屏才看得清。
- 硬伤：播放在手机，需要"编排在桌面 → 手机扫码接场"的交接设计。
- 结论：**与 A 同期做**，因为②场前编排是产品差异化的主战场。

**E. Skill / MCP / API**
- 优点：1-3 周可交付，直接挂到 Mobile Agent / WorkBuddy / 其他 agent；不用获客，借宿主的分发。
- 硬伤：没有自己的用户和品牌，随时被宿主替代。
- 结论：**作为分发补充，不做主线**。但设备桥（已建）就是这一层，保留。

**F. 硬件播放盒**
- 优点：B 端最稳（咖啡馆/健身房不用管手机），按年收服务费。
- 硬伤：供应链、认证、售后——现阶段是致命分心。
- 结论：**B 端验证 20 家以上再考虑**。

## 2. 推荐路径（四个阶段，每阶段有明确出口）

### 阶段 0：判断层先行（现在 - 3 周）

| 做什么 | 交付物 | 出口条件 |
|---|---|---|
| 50 首标注 + 9 张场合卡 + 12 条规则 | `ambience-system v1.0` 冻结 | κ ≥ 0.6、α ≥ 0.7 |
| 离线对照实验 | 盲评报告 | 体系 vs 直觉胜率 ≥ 70% |

**为什么先做这个**：如果 H3（场合→参数映射不成立）被证伪，后面所有形态都白做。这是最便宜的一次证伪机会。

### 阶段 1：H5/PWA + 桌面编排台（4-6 周）

- **C 端 H5**：场景卡选择 → 一分钟出歌单 → 一键唤起酷狗（Android）；iOS 降级为复制深链。
- **桌面编排台**：三栏界面（曲池 / 能量曲线时间线 / 校验），导出 `plan` + 清单 + 分享卡。
- **交接**：桌面排完生成二维码，手机扫码接场。
- **出口**：50 个真实用户、首播成功率 ≥ 70%、7 日复用 ≥ 30%。

### 阶段 2：原生 Android App（10-12 周）

- 把 H5 的三段体验原生实现；加推送（"周五了，今晚聚会的歌单排好了"）、离线、桌面图标。
- 内嵌设备桥轮询（已在跑），支持"到点自动开播"。
- **出口**：次日留存 ≥ 25%，周活 ≥ 500。

### 阶段 3：B 端控制台（8-10 周，与阶段 2 并行）

- 多场地/多时段排程（一家咖啡馆一周 7 天 × 3 时段）
- 场合卡版本管理 + 总部下发 + 门店微调
- 播放监控（实际在放什么、跳过率、设备在线）
- 权限与审计（谁改了什么卡）
- **出口**：3 家付费试点（咖啡馆/健身房/婚礼策划各 1），月费 ≥ ¥299/店。

### 阶段 4：生态接入（持续）

- Skill / MCP 让手机助手与其他 agent 调用判断层（"小艺，让 DJ Agent 排个婚礼晚宴的歌单"）
- 与手机厂商 A2A 合作（长期变量，微信 A2A 已跑通，音乐场景是自然延伸）

## 3. 三层的具体形态描述（给设计/开发看）

### ① 判断层（无形，是资产）

```
输入：场合描述 / 场合卡 ID / 参考曲
输出：plan（曲目序列 + 轴值 + 理由 + 规则版本）
接口：HTTP（/plan、/card、/track）、MCP 工具、Skill 文件
```

它不认识界面、不认识播放器、不认识平台——换壳不影响它。

### ② C 端（有形的门面）

三个页面，一条主线：

```
[场景卡]  →  [编排]  →  [现场盘]
 2 次点击     曲线+校验     5 个动作
```

不做：社区、评论、关注、歌单广场、会员体系（本期）。

### ③ B 端（有形的后台）

四个模块：**排程**（日历 × 场地 × 时段）、**卡片库**（版本/下发/审核）、**监控**（实时在放 + 跳过率）、**复盘**（周报：哪张卡表现差、建议怎么改）。

## 4. 变现假设（未验证，仅列结构）

| 对象 | 收费点 | 参考价 | 前提 |
|---|---|---|---|
| C 端个人 | 高级编排（长时长/多场景模板/导出） | ¥9-19/月 | 留存验证后 |
| B 端门店 | 按店月费（含排程+监控+卡片） | ¥299-999/月 | 3 家试点付费 |
| B 端连锁 | 总部授权 + 门店数阶梯 | 年框 | 10 店以上 |
| 生态 | 判断层 API 调用 | 按次 | 有 agent 方接入 |

**明确不做**：卖音乐（版权）、卖硬件（现阶段）、向 C 端卖广告。

## 5. 形态选择的风险对照

| 风险 | 影响形态 | 缓解 |
|---|---|---|
| iOS 无法唤起第三方 App | A/C | iOS 只做"复制深链 + 提示"，不承诺一键播放 |
| 微信小程序不能拉外部 App | B | 不做首发；仅作分享落地页 |
| 酷狗深链协议变更 | 全部 | 协议检测 + 多通道降级（已实现三通道）+ 关注版本 |
| 音乐版权投诉 | A/B | 不托管音频、不缓存音源，只做索引与跳转 |
| 平台审核（音乐类） | C | 准备版权说明：仅推荐与跳转，不提供播放 |
| B 端现场事故 | C/B 端 | 只读池 + 离线缓存 + 3 秒撤销（已设计） |

## 6. 一句话回答"最终长什么样"

**用户侧**：手机上打开一个链接（或 App），说一句"周六下午咖啡馆"，看到一条能量曲线和 14 首歌，点一下，酷狗开始放；中间觉得不对，拇指按一下"更炸"。

**商家侧**：总部在后台把"工作日下午"这张卡改一版，下发给 12 家门店，第二天生效；周末看报表，发现 A 店跳过率异常，点进去看是哪几首被跳。

**开发侧**：判断层是一套 JSON 契约 + 12 条规则；换壳（H5/App/小程序/API）不影响判断。
